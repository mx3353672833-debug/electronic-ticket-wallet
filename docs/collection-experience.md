# 收藏体验与补充信息

## 本轮设计方向

这是回看旅程的票夹，不是等待逐项审批的录入后台。保留地图与真实票面作为主角；完整收藏不显示通过章或核对状态。醒目的动作只留给缺少信息的那几项。

沿用纸白 #f5f5f7、浮层白 #ffffff、主字 #1d1d1f、辅助字 #737378、分隔线 #dedee3、交互蓝 #007aff。标题为系统 SF/PingFang Medium，正文为同系统 Regular，日期与数值使用现有等宽/表格数字样式。没有新增字体请求、装饰卡片或另一种首页。

布局比较：把所有字段永久放在侧栏会继续强调“录入”；改为旅程与故事先出现，票面信息和线路操作按需展开。签名体验仍然是原票在地图和阅读区之间的连续过渡，这轮不再添加另一组吸引注意力的动画。

```
大票面 → 旅程笔记 → 写故事（只一个文本框）
       → 待补充：日期 → 只填写日期 → 提示消失
                   票面信息 / 线路：需要时展开
```

## 完整性规则

- 必要：日期、出发地、到达地；火车/飞机/登机牌再要求车次或航班号。
- 选填：座位、票价、出发时间、故事、标签、同行者。没有 GPS 坐标或线路也不算票面资料缺失。
- 当前字段有值就正常展示，不依赖 `processing.reviewed`。不伪造“已人工核对”，不批量改写旧标记。
- 旧 OCR issues 留在源数据作诊断，不直接作为当前待办；补齐日期后不能继续提示旧的“日期未识别”。原图可查看，识别错字可编辑。
- 补充模式只提交缺失字段，写故事只提交 story；不随带整张票或图片 URL。已有坐标、票面和故事不被空表单清掉。
- 地图外收藏不等同于“待补充”：退票凭证和未定位收藏分别正常列示。

## 同轮改进

- 空格分隔的搜索词逐项匹配，支持“2025 北京”和全角车次输入；空搜索回车不打开任意票。
- 年份筛选后的数量按当前结果计算；完整票大图显示旅程日期与车次，不放扫描/核对字样。
- 隐藏空座位、空金额等诊断占位；写故事和编辑票面分开。桌面图标增加操作提示。

## 仍值得优先做，但不混入本次改动

1. **录入后直接看到刚加入的票。** 现在 ImportReport 只有计数，完成后按乘车日期排序，新录入的旧票容易滑到很远。可返回本批 ticket IDs，提供“查看刚收录的票”和只重试失败文件；保留原去重与原子保存。
2. **重叠票先给可选择的同组票带。** 现在聚合靠放大，几张票在同一点时需到高缩放再散开。可在保持地图视角的同时列日期/车次，再由用户选择“放大地图”，减少来回缩放。
3. **手机票面采用直接手势。** 当前放大是固定 150%，触摸只处理左右换票。可以引入已维护的手势组件实现双指缩放、双击复位，并把单指拖图与换票区分；需要真机 Safari/Android 验收。
4. **补站点后自动补线路。** 当前修改日期/站点会撤下旧线路，需要再手动更新。应先做站名建议/坐标匹配，再在后台请求线路；失败保留补好的票面信息，不能卡住保存或替换用户 GPX。

这些是从现有路径和代码找到的改进项，不是已上线承诺。背景录入/手势/同组选择会改变交互状态机，应逐项验收。
