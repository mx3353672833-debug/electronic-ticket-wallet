# 车次数据来源与接入边界

核查日期：2026-09-21。v0.3.0 已接入 RailGo 车次停站查询。

## 已核查来源

- [12306 官方车次查询](https://mobile.12306.cn/weixin/wxcore/initCC)：页面提供车次及日期输入。不能仅凭输入框就推定可以查询任意历史年份。
- [RailGo API](https://api.railgo.dev/)：[V2 车次查询](https://api.railgo.dev/479755220e0) 接收车次、日期；[V1 车次详情](https://api.railgo.dev/366464494e0) 提供可用的同车次时刻表；[MapLine](https://api.railgo.dev/479769351e0) 的车站坐标用于同名站、更名站匹配，GCJ-02 坐标通过 MIT 许可的 gcoord 转为 WGS84。
- [CnOpenData 全国列车时刻表](https://www.cnopendata.com/data/m/geography_traffic/railway.html)：产品说明覆盖 2007 年、2009—2024 年，按年度提供，含车次、站序、站名及到发时间等字段。购买需洽谈授权；不是免费的完整逐日历史 API。本次没有采购或下载付费库。

## 使用限制

RailGo 的当前使用说明要求非商业使用、公开展示时注明来源，禁止公开转发 API，并有限流要求。本服务只处理登录用户自己的票据，外部请求串行执行、至少相隔 1.5 秒，限流后冷却；不做全库抓取。不向数据源上传票面照片、身份信息或 OCR 全文。收费或其他商业用途需另行取得许可。

相关 [RailGo-Parser 仓库](https://github.com/RailGoApps/RailGo-Parser) 可作为数据处理流程参考；核查时未在仓库根目录看到明确许可证，不能默认复制代码到本项目。项目的 MIT 许可也不覆盖第三方时刻表和 OSM 数据。

## 接入顺序及验收

1. 使用票面车次、乘车日期查询时刻表，跨日乘车回溯始发日期；对应日期无数据时使用可用的同车次时刻表。来源、查询时间、适用日期和回退方式保存在数据中。
2. 按顺序截取上车站至下车站的区间，处理同名站、换号车次及跨日到发；禁止按无序站名集合连线。
3. 用有序停站约束 OSM 铁路图，逐段经过各站，保留原线段顶点。车站位于长线段中间时拆分原线段，不用直线连接地图缺口。
4. 缓存区分车次、日期、上下车站、算法和路网版本。时刻表缓存一天、线路缓存七天。GPS 导入优先，查询失败保留原线路；查询期间修改车次信息会阻止旧结果写回。
5. 合成测试覆盖同起终点不同停站、缺站、跨日车次、旧日期回退、坐标转换、缓存与限流、账号隔离、编辑并发和 GPX 保护。前端显示车次、里程、经停站与必要来源署名，不反复显示技术性免责声明。

## 历史库怎样取得授权

[CnOpenData 产品页](https://www.cnopendata.com/data/m/geography_traffic/railway.html) 销售联系人：李宇思，`liyusi@cnopendata.com`，微信 `CnOpenData-lys`。报价按数据范围洽谈，不必先采购全库。

说明用途是邀请注册的在线票夹，不是仅用于个人论文的数据下载。先索取具体年份覆盖清单和样例，再确认：

- 所需年份及车次、站序、站名、站码、到发时刻和版本生效日期字段。
- 能否保存在自己的服务器、供注册用户生成并展示衍生线路；不提供原始库下载。
- 缓存、备份、授权期限、到期后数据保留与更新方式。
- 按指定年份采购的价格；未来增加用户或收费是否需要另行授权。

可复制给供应商：
