# 车次数据来源与接入边界

核查日期：2026-09-21。以下是来源调查，不是已完成的路线接入。

## 已核查来源

- [12306 官方车次查询](https://mobile.12306.cn/weixin/wxcore/initCC)：页面提供车次及日期输入。不能仅凭输入框就推定可以查询任意历史年份。
- [RailGo API](https://api.railgo.dev/)：有车次、车站及站到站查询文档。[站到站查询](https://api.railgo.dev/366464961e0) 返回停站序列等信息。本次实测文档指定的 V1 服务 `https://data.railgo.zenglingkun.cn/api/train/sts_query?from=BJP&to=SHH&date=20260921&city=false`，HTTP 200、4 条结果；G5 与 1461 的停站顺序不同。这个通用样例证明数据可查询，不是对任何私人历史行程的核实。
- [CnOpenData 全国列车时刻表](https://www.cnopendata.com/data/m/geography_traffic/railway.html)：产品说明覆盖 2007 年、2009—2024 年，按年度提供，含车次、站序、站名及到发时间等字段。购买需洽谈授权；不是免费的完整逐日历史 API。本次没有采购或下载付费库。

## 使用限制

RailGo 的当前使用说明要求非商业使用、公开展示时注明来源，禁止公开转发 API，并有限流要求；批量处理需另行评估其支持方式。上线集成前复核最新条款，不把本服务变成公开代理，不向数据源上传票面照片、身份信息或 OCR 全文。无需 API Key 不等于没有使用条件。

相关 [RailGo-Parser 仓库](https://github.com/RailGoApps/RailGo-Parser) 可作为数据处理流程参考；核查时未在仓库根目录看到明确许可证，不能默认复制代码到本项目。项目的 MIT 许可也不覆盖第三方时刻表和 OSM 数据。

## 接入顺序及验收

1. 使用票面车次、乘车日期查询时刻表，并保存来源、查询时间和数据适用日期。历史日期无法覆盖时保留「未核实」，不可用今天的运行图默默替换旧行程。
2. 按顺序截取上车站至下车站的区间，处理同名站、换号车次及跨日到发；禁止按无序站名集合连线。
3. 用有序停站及可获得的经由线信息约束现有 OSM 铁路图。停站之间仍可能有多条线路，不能把最短路推断包装成已核实车次经由。
4. 缓存至少区分车次、旅行日期／适用版本、上下车站、数据来源和路网版本。保留原轨迹，GPS 导入仍可优先覆盖。
5. 用同起终点不同车次、改线前后日期、无历史数据、跨日车次、接口超时及限流的合成用例验收；最后浏览器检查不同车次确实显示对应路径和证据等级。

目前线上路线仍是起终站与车型类别约束的路网推算。以上数据源尚未接入，不应宣布已完成历史真实路线还原。
