# 统一票面外观

从 0.4.0 起接入私密服务器：新上传默认整理外观，地图、票据栏和大图使用同一套衍生图。已有扫描可通过整理流程补充外观，不重新识别文字或修改故事、日期与线路。没有 Change Style 选择器；大图仍可「查看原图」。这不是新的原件，也不是文字修复结果。

## 处理方式

`scripts/ticket-appearance.py` 对已经拉正、横向的同版式火车票进行：

1. 在临时估计层用 OpenCV 形态学闭运算抑制细小印字，提取参考票的大尺度纸色和底纹。
2. 将每张源票拆为缓慢变化的纸色/光照场及细节比值层，后者保留照片中的文字、纸纹、细折痕、掉墨等。
3. 将源细节合成到同一参考纸面上，统一展示尺寸和基础色调。蓝色底带已磨掉的样本不强行恢复底带。
4. 保守清理与边界相连的棕色桌面，输出带透明边缘的无损 WebP 大图与缩略图；保留凹口，不统一套圆角矩形。

登机牌及不匹配长宽比的票面保留自身版式、比例与品牌颜色，只做保守白平衡及边缘整理，不强制套用蓝色车票。各账号默认使用无印字的程序化纸面；可选参考票只从当前账号自己的私密收藏读取，不共享用户照片或残留纹理。

全部是确定性的传统图像处理，无生图、云端推理、OCR 重排或文字补全。临时背景估计使用的传统修补只用于纸色估计，不修补源票文字。

## 本地复现

安装到独立虚拟环境，不改全局 Python 环境；每份输出的 `recipe.json` 记录实际依赖版本及脚本 SHA-256。

```bash
python3 -m venv .local-data/ticket-look-venv
.local-data/ticket-look-venv/bin/pip install opencv-python-headless numpy pillow
.local-data/ticket-look-venv/bin/python scripts/ticket-appearance.py \
  /absolute/path/to/rectified-ticket.jpg \
  --production --kind train \
  --out .local-data/appearance-new-sample
.local-data/ticket-look-venv/bin/python scripts/ticket-appearance-test.py
```

输出目录必须不存在，拒绝覆盖。源文件只读，前后校验 SHA-256。生产输出为 `processed.webp`、`thumbnail.webp` 和 `recipe.json`。可选 `--reference /absolute/path/to/own-reference.jpg` 仅用于当前账号自己的参考票。省略 `--production` 并提供参考票可运行原离线样张模式，输出 PNG 和中间估计层供本地检查。

原相机照片、旧扫描与旧缩略图不覆盖；外观配方记录源图引用与校验值。逻辑引用仍为 `idb://images/...`，展示地址不得写回元数据。本机导出包含外观处理前的扫描引用；服务器备份应包含完整私密收藏目录。同版本重复处理不再生成图片；服务串行执行处理，检查账号归属和空间，导入失败回收本次新增文件。

## 适用边界

- 同版式蓝色火车票统一纸色；登机牌保留自身颜色。尚未实现任意票种的智能版式分类。
- 这是尺度分解，不是能准确理解磨损语义的分割器。宽污渍、褪掉的底纹、泛黄与光照的区分还需要逐张检查。
- 边界规则仅针对这批棕色桌面背景。棕色破损纸边可能与桌面混淆；参数激进时会误切纸张，因此采用保守连通规则。极细残边仍需手动微调，不能直接宣称任意照片自动抠图完成。
- 参考底板必须留在当前用户的私密目录，不可把某用户的扫描或其残留纹理作为公开或跨账号模板。
- 所有真实样张、原图、细节层和纸色估计图只放 `.local-data/`，不进 `public/`、Git 或公开托管。
- 既有收藏的批量处理需用户授权并先备份，合并时只改衍生图引用和处理配方，保留最新故事与线路。本机 IndexedDB 上传未改为服务器同步。

## 验证

合成测试覆盖色偏/亮度收敛、断墨不补字、参考印字不迁移、缺口与内部污点、褪色底带、原字节不变、确定性输出、拒绝覆盖、生产输出和登机牌比例。服务测试覆盖账号隔离、CSRF、配额失败恢复、重复请求与自动导入；界面测试覆盖默认衍生图、缩略图与原图切换。自动测试不能证明所有真实磨损均已正确提取。
